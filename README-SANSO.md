# เชื่อม SerpApi Lens และ Brave Web Search กับ SANSO

## 1. รับ API Key สองตัว

1. เปิด https://serpapi.com/manage-api-key เข้าบัญชี แล้วคัดลอก Private API Key
2. เปิด https://api-dashboard.search.brave.com/ เปิดใช้งานแพ็กเกจ Search แล้วไปที่ API Keys เพื่อสร้างและคัดลอกคีย์
3. เปิด https://vercel.com/dashboard → โปรเจกต์ `san` → Settings → Environment Variables → Add New

| Name | Value | Environment |
|---|---|---|
| `SERPAPI_API_KEY` | Private API Key จาก SerpApi | Production |
| `BRAVE_SEARCH_API_KEY` | คีย์จาก Brave Search API | Production |

กด Save หลังเพิ่มแต่ละตัว วางค่าเฉพาะใน Vercel และใช้ `GEMINI_API_KEY` กับ `DATABASE_URL` ที่มีอยู่ หากทดสอบผ่าน Preview ให้เลือก Preview สำหรับคีย์ที่ deployment ทดสอบต้องใช้ด้วย

## 2. อัปโหลดไฟล์

แตก ZIP เปิด https://github.com/johngrabana-cloud/san → Code → `main` → Add file → Upload files แล้วลากไฟล์และโฟลเดอร์จากภายใน ZIP ลงไป ให้ชื่อปรากฏครบอย่างละหนึ่งรายการ จากนั้นกด Commit changes ลง `main`

| ตำแหน่ง | หน้าที่ |
|---|---|
| `index.html` | แสดงสถานะคีย์ ผลค้น และภาพที่รอตรวจในหน้าร่าง |
| `package.json` | ติดตั้ง sharp เพื่อย่อสำเนารูปที่ส่งให้ Lens |
| `api/product-history/status.mjs` | ตรวจ Gemini และฐานข้อมูล พร้อมรายงานว่าพบคีย์ค้นหาหรือยัง |
| `api/product-history/questions.mjs` | ส่งผลค้นเป็นเบาะแสให้ Gemini ตั้งคำถาม |
| `api/product-history/generate.mjs` | ร่างประวัติจากคำตอบและผลค้น จัดรายการภาพอ้างอิง |
| `lib/product-history.mjs` | ตรวจสิทธิ์ตามข้อมูลการสแกนและส่งรูปให้ Gemini |
| `lib/product-history-search.mjs` | อัปโหลดสำเนารูปหลักให้ SerpApi และค้นเว็บผ่าน Brave |
| `README-SANSO.md` | คู่มือนี้ อัปโหลดได้ตามสะดวก |

เก็บ `api/product-history/scan.mjs` ใน GitHub ไว้เพื่อจับคู่รูปกับ Neon หาก GitHub ขึ้น HTTP 400 ให้เปิดหน้า Upload files ใหม่ แล้วอัปโหลด `api`, `lib` และ `package.json` พร้อมกันในรอบแรก จากนั้นอัปโหลด `index.html` ในรอบที่สอง

## 3. ทดสอบบนเว็บ

1. ไปที่ Vercel → `san` → Deployments ตรวจว่ารายการ Production ของ commit ล่าสุดขึ้น Ready หากตั้งคีย์หลัง deploy ให้กดเมนู ⋯ ของรายการล่าสุด → Redeploy
2. เปิด https://san-opal.vercel.app/ แล้วกด Ctrl+F5
3. เข้าแอดมิน → ตั้งค่า Gemini API → ทดสอบการเชื่อมต่อ ดูว่า Gemini และฐานข้อมูลขึ้น “เชื่อมต่อแล้ว” และ SerpApi Lens กับ Brave Web Search ขึ้น “ตั้งคีย์แล้ว” สถานะของสองคีย์นี้ตรวจว่ามีค่าใน Vercel การค้นสินค้าจริงจะตรวจการใช้คีย์และแพ็กเกจ
4. เลือก “เรียก Backend จริง” ติ๊ก “ให้ร้านยืนยันรายละเอียดและส่งรูปอ้างอิงให้แอดมินตรวจก่อนเผยแพร่” แล้วกด “บันทึกและใช้ Prompt นี้” ใช้ Prompt เดิมได้ ระบบเพิ่มผลค้นใน Backend
5. ใช้เบราว์เซอร์เดิมเข้า Seller Centre เลือกสินค้ามือสองที่รูปหลักทุกภาพผ่านการจับคู่ใน Neon ตอบคำถามของร้านและแนบหลักฐานได้ตามต้องการ
6. เปิด “ตัวอย่างเรื่องราว” ในร่างเดิมกด “ค้นเว็บและร่างใหม่” ตรวจสถานะของ Lens และ Brave จากนั้นเลือกภาพอ้างอิงที่ต้องการเสนอ พร้อมเปิดลิงก์ดูแหล่งต้นทาง ส่งแอดมินตรวจ
7. ในเบราว์เซอร์เดิมสลับเป็นแอดมิน เปิด “สแกนสินค้าเพื่อวางขาย” → “สินค้าที่มีประวัติรองรับ” → “ดูเรื่องราวและหลักฐาน” ตรวจรุ่น คำบรรยายต้นทาง และสิทธิ์ใช้ภาพก่อนอนุมัติ

## อ่านสถานะการค้น

- “พบผลค้น” หมายถึง API คืนลิงก์หรือภาพสำหรับตรวจสอบ
- “ไม่พบผลค้น” หมายถึง API ตอบกลับแล้ว แต่ไม่มีรายการที่แสดงได้
- “ตรวจคีย์และสิทธิ์ของแพ็กเกจ” หรือ “ตรวจโควตาหรือแพ็กเกจ” ให้ตรวจจาก Dashboard ของผู้ให้บริการและลองค้นอีกครั้ง
- “ไม่พบชุดรูปที่ตรงครบในฐานข้อมูล” ให้ตรวจรูปหลักและรายการอ้างอิงใน Neon การค้นเริ่มหลังผ่านเงื่อนไข SHA-256 ของระบบเดิม
- เมื่อ Brave ไม่มีข้อมูลที่ใช้อ้างอิงได้ ช่องประวัติจาก Gemini จะว่าง แต่ยังดูข้อมูลที่ร้านตอบและภาพที่ Lens พบได้

ในแต่ละรอบสร้างคำถามและสร้างร่าง ระบบค้นจากรูปหลักใบแรกและค้น Brave จากข้อมูลสินค้า รูปหลักที่ผ่านการตรวจจะถูกส่งเป็น JPEG ย่อให้ SerpApi ผ่าน Image API รูปหลักฐานเพิ่มเติมใช้ใน Gemini ตอนร่างประวัติ ภาพจาก Lens จะแสดงเป็นภาพคล้ายให้ตรวจสอบ แอดมินยังต้องอนุมัติก่อนเผยแพร่
